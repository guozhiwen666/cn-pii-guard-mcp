# cn-pii-guard-mcp

> 中文敏感信息识别、校验与脱敏 MCP 服务。纯离线，零密钥，一条命令可用。

给 AI Agent 一个"数据合规"的手：把一段日志、工单或数据库导出丢进来，它告诉你里面有哪些敏感信息、**哪些是真的合法、哪些只是长得像**，并按要求脱敏后返回。

## 为什么做这个

翻一遍魔搭 MCP 广场会发现一件事：上架的数千个服务里，绝大多数是"大厂 API 包装"——地图、搜索、支付、图像生成、金融数据、法律数据、钉钉办公。它们有几个共同点：要申请密钥、要授权、要计费、要联网。

而"脱敏"这类能力，目前主要是**企业级大模型安全网关**在提供的付费能力，广场上缺少一个免费的轻量替代。

于是就有了这个项目：**不需要任何密钥、不联网、不需要授权，装上就能用。**

## 四个工具

刻意只做四个。工具数是上下文成本，每多一个都在挤占模型真正的工作空间。

| 工具 | 作用 |
|---|---|
| `scan_sensitive_info` | 扫描文本，返回命中清单 + 风险分级 + 合法性判定 |
| `validate_identifier` | 校验单个证件/编码，执行完整校验位算法 |
| `mask_text` | 按策略脱敏，返回脱敏文本与逐项替换明细 |
| `generate_test_identifiers` | 生成能通过校验位的测试数据，用于构造测试样本 |

支持识别：居民身份证号、统一社会信用代码、银行卡号、手机号、电子邮箱、IPv4、中国大陆车牌。

## 和其他脱敏工具的区别

大多数脱敏工具是"正则一匹配、替换成星号"。这个项目多做了两件事。

### 1. 真校验位，不是"看起来像"

身份证走 GB 11643 的加权模 11，统一社会信用代码走 GB 32100 的模 31 映射，银行卡走 Luhn。所以下面这种情况能分得开：

```
validate_identifier("id_card", "11010519491231002X")   # valid: true
validate_identifier("id_card", "110105194912310021")   # valid: false，校验位错误
```

纯正则工具会把两个都判成身份证号。

### 2. 误报控制：18 位纯数字的歧义只能靠校验位解决

这是实现时踩到的真问题。一个订单号 `991380013800099912`，恰好 18 位、恰好全是数字——**它的格式和身份证号完全一致，正则无法区分**。

所以本项目的取舍是：

- 默认**报出来**，但标记 `valid: false`，让人知道它只是形似；
- 需要干净结果时传 `include_invalid=False`，靠校验位把它滤掉。

同时用边界断言防止从超长数字串里切片段：

```
"流水号 991380013800099912345678"   # 0 命中
```

这两条都有回归测试盯着（见 `tests/test_core.py`）。

## 快速开始

> 依赖 **mcp >= 2.0**。注意 `pip install mcp` 现在装的是 2.x，而 2.x 把 `FastMCP` 改名为 `MCPServer`，
> 2025 年前的教程写法 `from mcp.server.fastmcp import FastMCP` 会直接报 ModuleNotFoundError。

```bash
pip install -r requirements.txt

# 本地客户端（stdio）
python server.py

# 魔搭托管部署（SSE）
python server.py --transport sse --host 0.0.0.0 --port 8000
```

客户端配置（`mcp.json`）：

```json
{
  "mcpServers": {
    "cn-pii-guard": {
      "command": "python",
      "args": ["server.py"]
    }
  }
}
```

试一句：

> 帮我看看这段里有哪些敏感信息，把身份证和手机号脱敏：
> `客户张三，身份证 11010519491231002X，手机 13800138000`

## 踩坑记录

两个真实踩到的坑，也是这个项目最值得讲的部分。

### 1. mcp 2.x 把 FastMCP 改名了

2025 年前后的 MCP 教程几乎全是 1.x 写法：

```python
from mcp.server.fastmcp import FastMCP      # 2.x 下直接崩
```

实际 `pip install mcp` 现在装的是 2.x，正确写法是：

```python
from mcp.server.mcpserver import MCPServer
```

`run()` 的 kwargs 会透传给 `run_sse_async` / `run_streamable_http_async`，所以 host/port 只在 streaming 传输下能传，stdio 分支不接受 kwargs——这一点不分支处理就会在切传输方式时崩。

### 2. 脱敏工具最阴险的误报：数字串内部切片段

同一个订单号 `991380013800099912` 一次踩了两个坑：

- 它**恰好 18 位纯数字**，格式和身份证号完全一致，正则区分不了；
- 它**内部第 3 位起恰好是 `13800138000`**，一个格式完全合法的手机号。

如果边界断言写得不严，脱敏时会把订单号中间一段改成星号，把无关业务数据毁掉。

解法：`(?<!\d)` / `(?!\d)` 双向边界断言，加上校验位判定做二次过滤。两者都有回归测试盯着。

## 已知边界

- 地址、姓名等人名实体不在识别范围内 —— 中文人名歧义太大，靠正则做不准，宁可不做。
- 车牌正则只覆盖中国大陆常见号牌格式。
- 脱敏结果不可逆（`hash` 策略除外，它按原文哈希，可跨表关联）。
- 本服务完全在本地进程内计算，不上传、不落盘、不联网。
